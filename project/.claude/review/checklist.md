# プロジェクトのレビュー観点

adversarial-review スキルが、共通・言語ごとの観点に加えて読む。このプロジェクトの仕様・構成・約束事に依存する観点だけを書く。
言語やプロジェクトに依存しない観点は `~/.claude/skills/adversarial-review/checklists/` 側に置く。

## 使い方

- レビューで観点に無い指摘が出たとき、レビューを通った後でバグが見つかったときは、実装したセッションが一般化してここに足す
- 近い項目があれば、足さずにその項目を直す
- 書くのは確かめる観点と確かめ方だけ (「何を確かめれば見つかったか」)。経緯 (どこで見つかったか、何が起きたか) は git の履歴に残るので書かない
- 約 14KB を超えたら、足す前に統合・削除して整理する (毎回読むため)

## 領域の索引

差分が触れる領域の項目だけを読めるよう、領域ごとに ID の接頭辞を決めて、ここに並べる。

| 領域 | 接頭辞 | 対象 |
|---|---|---|
| (例) データ保存 | `D-` | DB スキーマ、マイグレーション、永続化 |
| (例) 画面 | `U-` | 画面遷移、状態管理 |

## 項目

形式: `ID. 観点 — 確かめ方`
