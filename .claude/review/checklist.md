# プロジェクトのレビュー観点

adversarial-review スキルが、共通・言語ごとの観点に加えて読む。このプロジェクトの仕様・構成・約束事に依存する観点だけを書く。
言語やプロジェクトに依存しない観点は `~/.claude/skills/adversarial-review/checklists/` 側に置く。

## 使い方

- レビューで観点に無い指摘が出たとき、レビューを通った後でバグが見つかったときは、実装したセッションが一般化してここに足す
- 近い項目があれば、足さずにその項目を直す
- 書くのは確かめる観点と確かめ方だけ (「何を確かめれば見つかったか」)。経緯 (どこで見つかったか、何が起きたか) は git の履歴に残るので書かない
- 約 14KB を超えたら、足す前に統合・削除して整理する (毎回読むため)

## 領域の索引

差分が触れる領域の項目だけを読めるよう、領域ごとに ID の接頭辞を決めて、ここに並べる。

| 領域 | 接頭辞 | 対象 |
|---|---|---|
| ガード | `G-` | `user/hooks/guard-*.sh`、`user/settings.json` の deny / ask、`user/CLAUDE.md` のガードの節 |
| 配布 | `D-` | `init.sh`、`project/`、`templates/`、ルートの `.claude/`・`.githooks/` |
| 検証ループ | `V-` | `verify-on-stop.sh`、`verify.sh`、`pre-push` |

## 項目

形式: `ID. 観点 — 確かめ方`

G-01. ガードで止めた操作が、ほかの経路 (Edit / Write ツール、Read ツール、MCP ツール) でも同じ強さで止まるか。ガード、settings の deny / ask、CLAUDE.md の記述が同じ範囲を指しているか — 止めた操作ごとに、Bash・Edit・Read・MCP の 4 経路を表にして、どれで止まるかを埋める
G-02. 判定が今いるディレクトリの状態 (ブランチ、リモートの追跡 ref) に依存するとき、テストがその状態を作って試しているか — `test-guard.sh` の `GUARD_CWD` を切り替えて、状態ごとにケースがあるかを見る
G-03. 判定を足したとき、既存のテストの期待値が、テストを動かす場所の状態によって変わらないか — 新しい判定が見る状態 (git リポジトリか、どのブランチか) を、既存のケースの実行場所で確かめる
D-01. 雛形 (`project/`) を変えたとき、ルートの同じファイル、README と SETUP.md の説明、`test-base.sh` のケースが追随しているか — 変えたファイル名で、ルートとドキュメントとテストを検索する
D-02. 配布で書き換えるファイル (プレースホルダを埋めるもの) が、再配布と `--force` で壊れないか — 初回 → 編集なしで 2 回目 → `--force` の順に `init.sh` を流して、表示と結果を見る
D-03. `user/` を変えたとき、`~/.claude` にも同じ変更が入っているか — `scripts/check-sync.sh` を通す
D-04. コマンド (`.claude/commands/*.md`) の手順で履歴を辿るとき (`git blame`、`git log`)、どのリビジョンを辿るか (修正の前か後か) と、行を足しただけの変更での扱いが書かれているか — 手順の通りに HEAD と修正前の両方で辿り、判定が変わらないかを見る
D-05. コマンドの手順に書いたシェルのコマンドが、共通のガード (`user/hooks/guard-bash.sh`) で止まらないか。止まるものは、ユーザーが実行するコマンドとして示す手順になっているか — 手順のコマンドを `test-guard.sh` と同じ形でガードに通す
D-06. ベースにスクリプトや CI を足したとき、README の構成の一覧、SETUP.md の手順番号、README の前提 (確かめていない環境など) が同じ回で更新されているか — 足したファイル名と、前提の記述を grep する。導入の確認 (`scripts/doctor.sh`) は、止めるべきでない操作を止める・登録の語だけの壊れた settings.json を通す入力で NG になるかを `test-base.sh` で試す。利用者の設定を書き換える処理 (`init.sh user --merge-settings`) は、フックが command を持たない・matcher が違う・名前が文字列に入るだけ・想定外の構造・書き込めない・連続実行を流し、配布が中断しないこと、既存の設定が変わらないことを確かめる
V-01. フックの出力が、届けたい相手 (Claude、ユーザー) に届く経路で出ているか — 終了コードと出力先の組を、Stop と UserPromptSubmit の仕様と照らす (シェルの観点 SH-12)
V-02. 検証ループから呼ぶスクリプトが `$HOME` や `CLAUDE_HOME` の下を読むようになったとき、そのスクリプトを呼ぶ既存のテストのすべてで、その場所が一時ディレクトリに差し替わっているか — `test-base.sh` で、そのスクリプトを呼ぶ箇所 (`hook()` を含む) の環境変数を確かめ、本物の場所に大きなファイルを置いた想定 (`CLAUDE_HOME` を差し替えて) でも通るかを見る
