# Go の観点

拡張子 `.go` のファイルに当てる。サーバー、CLI、並行処理を使うツールを想定している。バージョン依存の挙動 (ループ変数の扱いなど) は、`go.mod` の `go` の行を見て判断する。

### GO-01 エラーの握りつぶしと包み方
- 観点: 戻り値の `error` を `_` で捨てていないか。`if err != nil` の後に `return` を忘れて、続きを実行していないか。エラーを包むとき `%w` を使い、`errors.Is` / `errors.As` で比べているか (`==` や文字列の比較は包まれると外れる)。`defer` の中の `Close()` / `Flush()` のエラー (書き込みの失敗はここで出る) を見ているか
- 確かめ方: 各呼び出しの `error` の行き先を追う。ファイルの書き込みは `Close` の戻り値まで見る

### GO-02 nil の落とし穴
- 観点: 値が `nil` のポインタを入れたインターフェースは `nil` ではない (`var p *T = nil; var e error = p; e != nil`)。`error` を返す関数が型付きの `nil` を返していないか。`nil` の map への書き込みは panic (読み込みは可)。`nil` のスライスと空のスライスで、JSON の出力が `null` と `[]` に分かれる
- 確かめ方: 失敗しないパスで `err != nil` が真にならないか。空の結果を JSON にして見る

### GO-03 goroutine の終了とリーク
- 観点: 起動した goroutine が、いつ・どうやって終わるか。送信側・受信側のどちらかが先に抜けて、チャネルで永久に待たないか。`context` のキャンセルを見て抜けるか。`sync.WaitGroup` の `Add` を goroutine の中で呼んでいないか (`Wait` に間に合わない)。バッファなしのチャネルに、受け手がいない送信
- 確かめ方: キャンセルしたときに全 goroutine が戻るか。`-race` と、テスト後の goroutine 数 (`goleak` など) で見る

### GO-04 データ競合
- 観点: 複数の goroutine が、同じ map / スライス / 構造体のフィールドを、ロックなしで読み書きしていないか。map の並行アクセスは panic する。`sync.Mutex` を値で渡してコピーしていないか。ロックの範囲で、ロックを持ったまま外部の呼び出しやチャネルの操作をしていないか
- 確かめ方: `go test -race` を、並行に呼ばれる経路を通すテストで走らせる

### GO-05 ループ変数と defer
- 観点: ループの中で `go func() { use(v) }()` や `defer`、ポインタの取得 `&v` が、ループ変数を共有していないか (Go 1.22 より前は 1 つの変数が使い回される)。ループの中の `defer` は関数の終わりまで実行されず、ファイルや接続が溜まる
- 確かめ方: `go.mod` のバージョンを見る。ループで開いたリソースが、反復ごとに閉じられているか

### GO-06 context とタイムアウト
- 観点: `http.Client{}` / `http.Get` / `net.Dial` にタイムアウトがあるか (既定は無制限)。`context.WithTimeout` / `WithCancel` の `cancel` を `defer` で呼んでいるか。`context` を構造体に持たせず、第一引数で渡しているか。応答の `Body` を `Close` しているか (閉じないと接続が使い回されない)。受け取った `ctx` を下の呼び出しに渡しているか
- 確かめ方: 遅いサーバー (`httptest`) に対して、タイムアウトとキャンセルで戻ることを確かめる

### GO-07 整数・スライス・文字列
- 観点: `int` の桁あふれと、符号なし整数の引き算 (`uint(0) - 1`) の巻き戻り。`len(s)` はバイト数で、文字数ではない (`[]rune` か `utf8.RuneCountInString`)。スライスを `append` したとき、元の配列を共有したまま別のスライスに影響しないか。`s[a:b]` の添字が範囲外で panic しないか。サブスライスが大きな配列を保持し続けないか
- 確かめ方: 空、1 件、容量ぎりぎり、日本語や絵文字を含む文字列で試す

### GO-08 外から来る値の扱い
- 観点: `os/exec` に、外の値を `sh -c` で渡していないか (引数は別々に渡す)。`database/sql` に、`fmt.Sprintf` で作った SQL を渡していないか (`?` / `$1`)。`filepath.Join` に外の値を渡したとき `..` で外へ出ないか (`filepath.Clean` と、基準ディレクトリの下にあることの検査)。`html/template` と `text/template` の取り違え
- 確かめ方: `../x`、`a; touch x`、`' OR '1'='1` を入れて、実際に実行されるものを見る

### GO-09 テストと実行環境
- 観点: テーブルテストで、ケースの名前が重複していないか、`t.Parallel()` とループ変数の共有が混ざっていないか。`time.Now()` や `time.Sleep` に依存して、遅い環境で壊れないか。`init()` と、パッケージ直下の変数への副作用が、テストの順序に影響しないか。ビルドタグと、OS 依存のファイル (`_linux.go`) の片側だけが検証されていないか
- 確かめ方: `go test -race -count=3 -shuffle=on ./...` を通す。別の `GOOS` で `go vet` を通す
